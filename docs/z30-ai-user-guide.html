Z30 AI 使用文档

本文用于指导普通用户从注册开始，完成充值、创建 API Key、接入 Codex/Claude/Gemini 类客户端，并在遇到余额、分组、网络、状态码等问题时快速定位原因。

推荐站点：z30.top 更新日期：2026-06-21 适用对象：Z30 AI API 使用者

使用前先了解

请注意：不同站点会按运营配置隐藏或开放部分功能，例如支付方式、订阅套餐、邀请返利、可用渠道等。本文按 Z30 AI 当前用户端常见界面编写，实际以你的站点页面显示为准。

余额与倍率

请求会按模型价格和分组倍率扣除余额。选择 Key 分组时，页面会展示对应平台、倍率和可用模型，请以页面显示为准。

可用分组

API Key 必须绑定一个可用分组。Codex/GPT、Claude、Gemini 等客户端应选择对应平台的分组，否则可能出现模型不可用或接口不匹配。

用量记录

每次 API 请求都会生成用量记录。排查问题时优先查看请求时间、Key、分组、模型、扣费和错误信息。

从零开始使用 Z30 AI

新用户只需要完成三件事：注册账号、充值或购买套餐、创建 API Key。Key 创建后可直接在 Codex、Claude Code、Gemini CLI、OpenCode 或其他兼容客户端中使用。

1. 注册用户

打开站点首页，进入 注册 页面。常见入口为 /register。
按页面提示填写邮箱、用户名、密码和验证码。如果站点开启邀请码，注册时需要填写管理员或邀请人提供的邀请码。
如果使用第三方登录，例如 GitHub、Google、LinuxDo、微信、钉钉或 OIDC，请按授权页提示完成绑定。部分 OAuth 注册仍可能要求补充邮箱或邀请码。

2. 登录成功后

登录后默认进入用户仪表盘。这里会展示账户余额、今日用量、近期请求、模型用量趋势、订阅状态和快捷入口。

页面 用途
仪表盘 查看余额、总体用量、近期请求和图表。
API Keys 创建、复制、启停、删除 Key，设置分组、额度、过期时间、IP 黑白名单。
用量记录 查看每次请求的模型、Token、费用、状态和错误。
可用渠道/渠道状态 查看站点当前可用分组、模型和资源状态。
充值/我的订单 充值余额、购买订阅、查看支付订单状态。

3. 创建密钥

进入 API Keys，点击 创建 Key。
填写 Key 名称，例如 codex-plus-pool 或 claude-private，方便以后区分用途。
选择分组。使用 Codex/GPT 时选择 OpenAI/Codex 相关分组；使用 Claude Code 时选择 Anthropic/Claude 或 Antigravity Claude 相关分组。
可选设置：自定义 Key、IP 白名单/黑名单、Key 总额度、5 小时/1 天/7 天速率额度、过期时间。
创建后复制 Key。需要配置客户端时点击表格里的 使用 Key，页面会自动生成适配当前分组的配置。

API Key 只展示一次完整值。复制后请妥善保存，不要发到公开群、GitHub 仓库、截图或日志中。如果怀疑泄露，请立即禁用或删除旧 Key 并重新创建。

如何充值

充值入口通常在左侧菜单的 购买订阅 或 充值 页面。站点可能同时提供余额充值和套餐订阅两种方式。

余额充值

适合按量付费。输入金额，选择支付方式，创建订单后扫码或跳转支付。支付完成后系统会自动到账。

订阅套餐

适合固定周期、固定分组或有日/月额度的使用方式。选择套餐后支付，套餐会显示在 我的订阅 中。

充值步骤

进入 购买订阅 页面，选择 充值 或 订阅 标签。
余额充值时输入金额；订阅时选择套餐。页面会显示实际支付金额、手续费和到账额度。
选择支付方式。常见方式包括支付宝、微信、Stripe、Airwallex 或站点接入的聚合支付。
完成支付后等待页面轮询订单状态。不要反复创建相同金额订单；如果页面未自动跳转，可到 我的订单 查看。

首次使用建议先以站点允许的最低金额或小额套餐测试：确认 Key 能创建、客户端能调用、分组速度符合预期后再追加充值。

Codex/GPT 系列模型使用指南

Codex/GPT 类客户端通常使用 OpenAI 兼容方式接入。推荐从站点 API Keys 页面点击 使用 Key，直接复制自动生成的配置。

网站注册后怎么接入 API 使用 Codex 插件 / Codex App / CLI

创建一个绑定 OpenAI/Codex 分组的 API Key。
确认 API Base URL。站点通常会在 API Keys 页面上方显示，也可能是 https://z30.top 或 https://z30.top/v1。
把页面生成的 config.toml 和 auth.json 写入本机 Codex 配置目录。

macOS / Linux：~/.codex/config.toml

config.toml 
model_provider = "OpenAI"
model = "gpt-5.5"
review_model = "gpt-5.5"
model_reasoning_effort = "xhigh"
disable_response_storage = true
network_access = "enabled"
windows_wsl_setup_acknowledged = true

[model_providers.OpenAI]
name = "OpenAI"
base_url = "https://z30.top"
wire_api = "responses"
requires_openai_auth = true

[features]
goals = true

macOS / Linux：~/.codex/auth.json

auth.json 
{
  "OPENAI_API_KEY": "替换为你的 Z30 AI Key"
}

Windows 路径

Windows 下通常放到 %USERPROFILE%\.codex\config.toml 和 %USERPROFILE%\.codex\auth.json。如果 Codex 运行在 WSL 内，则使用 WSL 用户目录下的 ~/.codex。

不要手工猜测 URL 是否需要 /v1。以站点 使用 Key 弹窗生成的配置为准，避免出现 404 Not Found 或路径重复。

网站注册后怎么接入 API 让 Claude 插件 / Claude CLI 使用 GPT 模型

部分站点会为 OpenAI/Codex 分组开启 Claude 兼容或消息分发能力。开启后，Claude Code 可以用 Anthropic 环境变量形式调用 GPT 分组。

macOS / Linux Terminal 
export ANTHROPIC_BASE_URL="https://z30.top"
export ANTHROPIC_AUTH_TOKEN="替换为你的 Z30 AI Key"
export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
PowerShell 
$env:ANTHROPIC_BASE_URL="https://z30.top"
$env:ANTHROPIC_AUTH_TOKEN="替换为你的 Z30 AI Key"
$env:CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1

VS Code Claude Code 配置

~/.claude/settings.json 
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://z30.top",
    "ANTHROPIC_AUTH_TOKEN": "替换为你的 Z30 AI Key",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1",
    "CLAUDE_CODE_ATTRIBUTION_HEADER": "0"
  }
}

如果 Claude 客户端仍显示 Claude/Opus/Sonnet 名称，不一定代表实际走的是 Claude 模型。请以站点 用量记录 里的请求模型、上游模型和分组为准。

Anthropic/Claude 系列模型使用指南

Claude 系列通常使用 Anthropic 兼容接口。创建 Key 时请选择 Anthropic/Claude 或 Antigravity Claude 相关分组。

生成 API Key

进入 API Keys，点击 创建 Key。
分组选择 Claude/Anthropic 或 Antigravity Claude 分组。
创建后点击 使用 Key，选择 Claude Code 标签。

导入 API Key

如果站点显示 导入到 CC-Switch 按钮，可以直接点击导入。也可以手动配置环境变量：

Claude Code 环境变量 
export ANTHROPIC_BASE_URL="https://z30.top"
export ANTHROPIC_AUTH_TOKEN="替换为你的 Z30 AI Key"
export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1

如果使用 Antigravity Claude 专用分组，Base URL 通常需要带 /antigravity：

Antigravity Claude 
export ANTHROPIC_BASE_URL="https://z30.top/antigravity"
export ANTHROPIC_AUTH_TOKEN="替换为你的 Z30 AI Key"
export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1

使用

配置完成后重新打开终端或重启客户端，再发起一次简单请求测试。建议先用短问题确认连通性，再进行大项目、大上下文任务。

Claude 原生账号和 Antigravity Claude 不建议混在同一个对话上下文里使用。长任务开始前先选好分组和模型，避免中途切换导致上下文异常。

Gemini 分组补充

如果站点开放 Gemini 分组，可使用 Gemini CLI 兼容环境变量：

Gemini CLI 
export GOOGLE_GEMINI_BASE_URL="https://z30.top"
export GEMINI_API_KEY="替换为你的 Z30 AI Key"
export GEMINI_MODEL="gemini-2.0-flash"

将 Z30 AI 作为自有转发站的上游（尚未完工）

该部分适用于自己已有 Sub2API、New-API 或其他转发站，希望把 Z30 AI 当作上游渠道的人。当前能力以站点实际开放为准，正式接入前请先小流量测试。

事先准备

  • 一个可用的 Z30 AI Key。
  • 明确要接入的分组平台：OpenAI/Codex、Anthropic/Claude、Gemini 或 Antigravity。
  • 确认 Base URL。优先使用 Z30 AI 页面生成的端点，不要自行拼接重复路径。
  • 准备限额策略，避免自有转发站用户把 Z30 AI Key 的余额一次性打空。

Sub2API

在自有 Sub2API 管理端添加上游账号或渠道时，选择与 Z30 AI 分组一致的平台类型，填入 Z30 AI Base URL 与 API Key。保存后用短请求测试，再逐步开放给用户。

New-API

在 New-API 管理后台新增渠道，选择 OpenAI 兼容或 Claude 兼容类型，填入 Base URL 和 Key。模型列表建议先只开放你确认可用的模型，避免用户请求不存在的模型造成 400/404。

该功能仍按“尚未完工”处理。生产使用前请确认站点规则允许二次转发，并设置好用量限制、错误重试和余额预警。

下载 Windows 环境下的常用工具

工具下载入口可能随项目更新变化。优先使用站点公告、群文件或工具官方 Release 页面提供的安装包，避免下载来源不明的压缩包。

工具 用途 建议

问题合集：充值用户

为什么从账号切换成 API 后之前的聊天记录看不见了？怎么才能看到之前的记录？
网页端账号聊天记录和 API 调用记录是两套系统。API 客户端不会自动读取你在 ChatGPT、Claude 或 Gemini 网页里的历史对话。需要继续使用旧记录时，请回到原网页账号查看，或手动复制上下文到 API 客户端新会话。
使用过程中出现问题怎么处理？
按顺序检查：余额是否充足、Key 是否启用、Key 绑定分组是否正确、Base URL 是否正确、客户端是否把 Key 写到了正确配置文件、用量记录里是否有错误、渠道状态是否可用。仍无法解决时，把错误码、请求时间、Key 名称、分组名和客户端截图发给客服。
为什么有时候推送速度这么慢？
常见原因包括模型繁忙、账号池资源紧张、请求上下文过长、输出太长、网络抖动或客户端正在重连。可以尝试新开会话、缩短上下文、换分组、稍后重试，或在渠道状态中观察可用资源。
分组倍率是什么意思？
倍率是站点计算请求费用时使用的系数。创建或编辑 Key 时，分组标签会显示平台和倍率；实际扣费以用量记录为准。
缓存命中率是什么？
部分上游模型会对重复上下文或前缀做缓存，命中后可能降低成本或加快响应。是否命中取决于模型、客户端请求形态和上游能力，不保证每次都有。
第一次使用 API，应该充值多少合适？
先用站点允许的最低充值金额或小额套餐测试。确认 Key 创建、客户端配置、分组速度和扣费都符合预期后，再根据自己的日常用量追加余额。
不充值上游官网账号，用量怎么办？
Z30 AI 用户端按平台余额或订阅额度扣费。你只需要保证 Z30 AI 账户余额或套餐额度充足，不需要在 OpenAI、Claude、Gemini 官网账号里单独充值。
充值时显示“商户余额不足，请联系商户进行充值”怎么办？
这是支付通道或商户侧状态问题，不是 API Key 问题。请换一个支付方式，或联系站点客服处理。不要连续创建大量待支付订单。
为什么经常说我的 Claude，模型识别后使用 gpt-5.5，问 Claude 它是什么模型时却回答 Opus 4.6？
模型自报身份不可靠，客户端系统提示词也可能让模型沿用 Claude/Codex 的表述。判断实际调用模型应看站点用量记录中的请求模型、上游模型、分组和计费记录。
我正在使用 Codex，应该选择哪个分组？
选择平台标识为 OpenAI/Codex/GPT 的可用分组。创建 Key 后可以先用小任务测试速度、稳定性和扣费；如果请求失败，再切换到另一个同平台分组。
渠道状态怎么看？如何观察账号池的状态？
进入 渠道状态 或 可用渠道 页面。重点看分组是否可用、支持模型、可用资源数、最近检测结果和延迟。普通用户只能看到站点开放给用户侧的状态信息。
为什么 PRO 号池和 TEAM 号池一直显示可用服务数/资源数状态？
部分账号池的真实额度、服务数或资源状态无法完整暴露给用户端，只能显示检测结果或估算状态。只要请求成功、用量记录正常，就说明该分组可用；如果持续失败，请切换其他分组并反馈。
我已经可以使用 Codex 的账号，但我想申请 GPT 系列模型怎么办？
创建 Key 时选择 OpenAI/Codex/GPT 相关分组，并按 Codex 配置方式接入。如果你的账号只被授权 Claude 或 Gemini 分组，需要联系管理员开通对应 GPT 分组权限。
我的 CC-Switch 检测站点可用性失败，是不是站点 API 有问题？
不一定。常见原因是 Base URL 填错、路径重复、检测接口不兼容、Key 未加 Bearer、Key 分组和客户端类型不匹配。建议先用站点 使用 Key 弹窗生成的配置导入，再用短请求验证。
本站可以翻译或生成图像吗？
翻译属于普通文本请求，只要模型可用即可。图像生成取决于站点是否开放图像模型、当前分组是否支持图像输出以及是否配置了图像计费。请在 可用渠道 中查看支持模型。

无法访问网站 / 无法访问 API 端点

先判断是网页打不开，还是网页能打开但 API 请求失败。两者排查方向不同。

测试 API 连通性 
curl -i "https://z30.top/v1/models" \
  -H "Authorization: Bearer 替换为你的 Z30 AI Key"
现象 可能原因 处理方式
网页打不开 本地 DNS、网络限制、站点维护、证书异常。 换网络、清 DNS、检查公告，必要时联系站点客服。
网页能打开，API 失败 Base URL、Key、分组、余额、客户端配置问题。 用上面的 curl 测试，核对 API Keys 页面生成的配置。
客户端一直重连 流式连接中断、代理干扰、模型响应过长。 关闭不稳定代理，缩短上下文，换分组或稍后重试。

Codex 客户端状态码 / 错误以及解决方案

状态码或提示 含义 解决方案
Reconnecting... (1/5) 客户端流式连接断开并重试。 等待自动重连；如反复出现，缩短上下文、换网络或换分组。
400 请求参数错误、模型名不支持、客户端发送了上游不支持字段。 检查模型名，更新客户端，使用站点生成配置。
401 Unauthorized API Key 错误、未带鉴权、Key 已删除或禁用。 重新复制 Key，确认请求头为 Authorization: Bearer sk-...。
403 Forbidden: insufficient_balance 余额不足或订阅额度不足。 充值、续费，或切换到仍有额度的 Key/分组。
404 Not Found 接口路径错误、Base URL 填错、重复拼接 /v1。 直接使用 使用 Key 弹窗生成的 URL。
413 Request Entity Too Large 请求体太大，文件或上下文超限。 减少文件、缩短对话、分批处理任务。
418 I'm a Teapot 站点或上游的特殊拒绝状态，常见于策略拦截或分组不可用。 查看返回消息和用量记录，切换分组后重试，必要时联系管理员。
429 Too Many Request 请求过快、并发过高或 Key/分组限流。 降低并发，等待窗口重置，或升级额度。
502 Bad Gateway 上游账号或网关临时异常。 稍后重试，或切换其他分组。
503 Service Unavailable 当前分组暂无可用账号或服务维护。 查看渠道状态，切换到 PLUS 共享池或兜底池。
网络请求超时 本地网络、代理、站点网关或上游响应超时。 缩短请求、换网络、稍后重试，持续出现时反馈请求时间和分组。

常见 Codex 报错信息

stream disconnected before completion: Incomplete response returned, reason: max_output_tokens
模型输出达到最大输出长度，流被截断。请让 Codex 分步骤处理、减少一次性输出、要求先给概要再继续，或新开一轮让它从上次位置续写。
Codex ran out of room in the model's context window. Start a new thread or clear earlier history before retrying.
上下文窗口满了。请新开会话、清理无关历史、减少粘贴的大文件内容，或把任务拆成多个较小问题。
Selected model is at capacity. Please try a different model.
所选模型当前容量不足。等待几分钟重试，或切换其他模型、其他分组、兜底池。
